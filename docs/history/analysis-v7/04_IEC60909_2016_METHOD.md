# IEC 60909-0:2016 method status

**Normative implementation and independent acceptance: BLOCKED. This feature does not complete IEC 60909-0:2016.** Mathematical positive-sequence acceptance and diagnostics are separate from that verdict. There is no IEC/PF-certified Ikss/Skss or Ip/Ib/Ith result.

## Source review

Requested edition: [IEC 60909-0:2016 Edition 2](https://webstore.iec.ch/en/publication/24100). The supplied ZIP's three notes/indexes and PF screenshots were inspected. The archive has no full normative text or independent numerical IEC examples. Owned PowerFactory 2024 External Grid, Voltage Source, Synchronous Machine and Two-Winding Transformer technical references were read locally; private PDFs and archive contents remain uncommitted.

PF 2024 Two-Winding Transformer Technical Reference §4.1, printed p39–40 (PDF p44–45), explicitly distinguishes 2016 MAX corrections from 2001, neutral taps, network transformer equation 12a, synchronous unit equations 22/24, and converter unit factor 1. An [older official FAQ](https://www.digsilent.de/en/faq-reader-powerfactory/why-are-the-results-of-short-citcuit-calculation-depending-on-max-voltage-tolerance.html) describes using MAX correction for MIN as well. This difference cannot be resolved by copying an isolated equation; effective edition, applicability and independent normative acceptance are required. No KT, KG or KKW rule has been silently applied to all native transformers/machines.

The [Thurner/Braun primary research paper](https://arxiv.org/abs/1802.01502) describes sparse voltage/current-source contributions and validation examples. It supports further method research; reading its abstract is not acceptance of the complete IEC method. No 2026 rule is imported into the 2016 profile.

## Implemented, versioned boundary

`ScProfile` and `ScResult` retain legacy fields and add schema version 2, requested edition, frequency, distinct breaker opening / thermal clearing times, method evidence and per-quantity support/reasons. Existing profiles with `edition:null` retain their numerical network approximation. An explicit 2016 request returns `GA_IEC60909_2016_PREFLIGHT`, BLOCKED faults, null quantities and **zero factors/RHS**; it never relabels a diagnostic result. Only code-owned normative acceptance could open that gate, not a checkbox, imported result or PF screenshot.

`method-evidence.ts` inventories active source families and native/assumed/missing inputs separately from normative verification. KG/KT/KKW, independent examples, motor/machine decay and meshed kappa are explicit blockers. Existing native source audit still handles units, service status, missing/sentinel data, MAX/MIN source context and explicit approximation overrides. Source-equivalent factor and fault voltage factor stay distinct.

`ikssKa`/`skssMva` support reports ENGINE_CALCULATED only for a successful mathematical network result. Ip requires supported source contributions and radial/meshed kappa, Ib requires near/far/decay and opening time, Ith requires separate AC/DC thermal factors and clearing time. Each unsupported quantity stays null with its own reason. LL/1LG/2LG remain blocked until sequence/grounding models are implemented.

`equipment-limits.ts` separates rated voltage, interrupting Ib, making peak Ip, and thermal Ith with matching duration and sourced ratings. Ikss alone cannot issue an interrupting/thermal safety verdict. This API is tested; automatic native equipment rating adaptation and its UI remain NOT_IMPLEMENTED.

## Sparse reuse and mathematical acceptance

Existing complex KLU factors are reused. Driving-point impedances now cache by actual electrical bus within the leased component preparation, so physical aliases and later batches reuse a RHS result; changed model/source/scenario invalidates it. Changed fault R/X recomputes current from cached Zkk. No dense full inverse or new SC solver is introduced.

17 targeted tests pass across `short-circuit` and `sc-method-evidence`. Existing independent 2/3/5-bus radial, parallel, non-unity transformer/tap/phase, high/low voltage base, switch, source/sentinel, cancellation and leased-cache tests remain. New tests prove normative requests cannot generate numerical values, legacy numeric equivalence, distinct time gates, alias reuse, source assumptions and independent equipment quantity checks. These are **mathematical/API tests, not normative IEC examples or PF parity**.

Required next evidence: authoritative 2016 equations/applicability, independently solved MAX/MIN network/machine/unit/converter/motor examples, source correction adapters, validated source-contribution/decay models, mesh kappa and thermal factors; then actual matching PF ComShc manifests and partitions. Full normative acceptance remains blocked until those pass.
