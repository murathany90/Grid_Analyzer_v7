# Legacy HTML module and dependency map

Source inspected: `YTBS_PowerFactory_Sebeke_Goruntuleyici_v6_8.html` (3,404 lines). The line references below are to that file as inspected; keep them until the first extraction commit, then replace them with module/function links. This map is an extraction aid, not a numerical review.

## Recommended extraction order

Preserve the existing calculations and move in dependency order. Do not start by moving whole `<script>` blocks: the file contains nested workers as text, multiple classic scripts that share top-level globals, and later monkey patches which intentionally replace earlier definitions.

1. Create a TypeScript `DgsModel` / importer module from the `DGSModel` class at lines 252–317. Keep its DGS table/index representation and normalization behavior intact. Its input is parsed JSON; it does not need DOM access. Move `parseJSONOffMain` (672) and the `loadFiles` orchestration (348–350) separately: the former owns browser Worker/Blob parsing fallback; the latter owns progress UI, calling `init`, `auditV2`, and model activation.
2. Extract electrical graph builders as explicit pure-ish functions taking a model and an override snapshot. There are three distinct products, so retain distinct entry points: display topology `calculateTopology` (629–634), reduced legacy AC `makeHVGraph` (703–836), and full-network `buildElectricalModel` (2883–2930). Do not conflate the display union-find graph with either solver graph.
3. Extract the full NR worker source verbatim into a solver module, then change the worker bootstrap to import/call it. The worker currently has no imports or exports and is read from a `type="text/plain"` script, converted to a Blob, and constructed by the host. Keep its self-tests with this module.
4. Extract host-side full AC model construction and result adaptation separately from the numerical kernel. The host currently has DGS access, scenario/UI state, timestamps, result-set installation, diagnostics, DOM status, and Worker lifecycle all in the same IIFE.
5. Preserve legacy Fast AC and DC behind adapters with explicit names. They are compatibility engines with different network scope and behavior from Full NR.
6. Migrate the versioned UI/integration patches last. Prefer explicit functions/composition over preserving global monkey patch order, but preserve each active behavior while replacing it.

## Overrides, stale alternatives, and deletion cautions

- **Still live and worth extracting:** `DGSModel` and loader; `calculateTopology`; reduced graph/AC worker and DC worker; full network builder; full NR worker; scenario snapshot/signature and result-store integration. `runFast` (2989) is explicitly an adapter to `startV3Solver`, while `runDc` (2990) calls `DCFlowEngine`; neither is dead just because Full NR exists.
- **Legacy topology is not one implementation:** `calculateTopology` at 629 is a UI diagnostic; `makeHVGraph` at 703 is the reduced ≥66 kV approximation; `buildElectricalModel` at 2883 creates the Full NR network. Keep the contracts separate.
- **Earlier visual/result functions are often wrapped, not dead:** `drawScheme`, `drawMap`, `showLine`, `selectLine`, `activateModel`, `setView`, `latestResult`, `renderAnalysis`, and `applyComputedIslands` have later wrappers/replacements. Only the final assigned function is the runtime entry point, but its saved `old/orig/previous` closure is a dependency; preserve the whole chain until replacement behavior is deliberately composed.
- **Potentially inert legacy upload path:** result-file parsing and normalization remain at 546–568, but external result/measurement controls are disabled by `disableLegacy` at 1158 and described as disabled in the UI. Do not migrate this alongside DGS import unless the product explicitly retains file imports.
- **Potentially superseded V3 hook:** the original `runSolver` click is assigned to `startV3Solver` at 863 and replaced at 1904; then v6 relabels the same control “Hızlı Yaklaşık AC” (2998–2999). The old `solveIsland` is not dead: `solveIslandV52` uses it for initial values (1001). The initial plain-text worker action handles `solveIslandV52` (1152).
- **No reliable dead-code deletion from text search alone:** hooks are referenced by string IDs, window exports, and closures. For the first TypeScript port, inventory remaining HTML-only functionality as compatibility code; delete only after static call/reference review and behavior review.

## Safe TypeScript seams

- `dgs/types.ts`, `dgs/DgsModel.ts`: DGS input tables, indexes, and model-enrichment methods; no DOM.
- `topology/displayTopology.ts`: display connected-component count; isolated from solver contracts.
- `solver/legacyFastAc.ts`: `makeHVGraph` + reduced model typing + worker kernel; explicit `ScenarioSnapshot` for lines, switches, restored terminals; retain “reduced ≥66 kV” identity in result metadata.
- `solver/legacyDc.ts`: `solveIslandDC` + DC flow engine with same explicit reduced graph type.
- `solver/fullNetworkBuilder.ts`: current `buildElectricalModel`; use DGS read interface and immutable `ScenarioSnapshot`; output plain `FullNetworkModel` and diagnostics.
- `solver/fullNr.ts`: pure numerical functions from worker source, including self-tests; accepts/returns structured-clone-safe data only.
- `solver/fullAcService.ts`: worker lifecycle, cache invalidation, stale result protection, result conversion/quality, and solver API. Give UI an injected status/result callback instead of `HTMLElement` globals.
- `scenario/ScenarioSnapshot.ts`: normalize line/switch/trafo/bus overrides and virtual restored terminals once; share one versioned signature with the builder and result store. Current state sources span `v4`, `v42`, `YTBS_V62_TRAFO_OVERRIDES`, `YTBS_V68_BUS_OVERRIDES`, `VirtualEnergizationEngine`, and `ScenarioController`.

Keep the first extraction mechanical: add import/export seams without changing formulas, iteration settings, rounding, state invalidation order, status taxonomy, or self-test fixtures. The current global coupling is the largest risk: builders read browser singletons and downstream result installation mutates multiple legacy stores.
