## Backend decision

| Candidate | Type / browser | Persistent factor and multi RHS | License / packaging / maintenance | Decision |
|---|---|---|---|---|
| [klu-js 0.1.0](https://github.com/rwl/klu-js) | SuiteSparse KLU nonsymmetric sparse LU, WASM, CSC | `klu_analyze` → `klu_factor` → `klu_solve(..., nrhs, ...)` | LGPL-2.1-or-later; 71 KB WASM embedded in portable HTML; upstream KLU mature but JS wrapper is a new 0.1.0 package with limited maintenance history | **Selected** |
| [SCS WASM](https://github.com/DominikPeters/scs.wasm) | Browser conic optimizer | No arbitrary nonsymmetric A*x=b factor handle | MIT; wrong numerical API | Rejected |
| [HiGHS WASM](https://github.com/the-aiway/highs-wasm) | Browser LP/MIP/QP optimizer | No arbitrary sparse LU multi-RHS API | MIT; larger and wrong numerical API | Rejected |

The npm wrapper ships classic-script wasm-bindgen glue despite its README's ESM example. The pinned package (`klu-js@0.1.0`) supplies the generated glue and WASM; the repository adds only an ESM export to a vendored glue copy and embeds the pinned WASM as base64. The full LGPL text is stored at `licenses/klu-js-LICENSE` and embedded in the standalone portable HTML with source attribution. This report does not assert that bundling alone settles every downstream LGPL distribution obligation. The wrapper's limited maintenance history remains a risk.

The `SparseDirectFactorization` adapter converts CSR to CSC once, performs one symbolic and one numeric factorization per classification state, solves all unique remote RHS in one packed call, disposes handles, and independently checks `||b−Ax||/||b|| ≤ 1e−6`. Production does not call ILU/GMRES/BiCGSTAB. Legacy Krylov remains explicitly selectable for diagnostics. No tolerance was relaxed.

## Synthetic and browser gates

The 8,100-dimensional synthetic nonsymmetric matrix had 52,867 nnz. One factorization: CSC 5.80 ms, symbolic 4.40 ms, numeric 26.85 ms. On that same factorization, solving 1 / 32 / 158 RHS took 2.97 / 16.80 / 70.80 ms wall time. All true residuals were below `9e−16`; factorization count stayed one. Adapter unit tests checked a known nonsymmetric system and multi RHS. A Chromium probe ran two KLU RHS with residuals below `1e−12`, and the portable HTML was verified to contain the WASM base64 and LGPL text without an external WASM reference.

The monotone active-set fixture retained two controllers through `5→3→2→2`; a second fixture verified that successful second-pass survivors are not discarded by the pass limit. Four classification passes is the maximum. A pass-four ownership change without a new stable probe is reported as unstable and cannot enter the coupled Q solve.

## Evidence-led decisions

**HYPOTHESIS:** A mature sparse direct solve would remove the 66-second RHS cost. **EVIDENCE:** 313/313 real RHS passed with maximum true residual `2.805e−10`; direct RHS solve was 29.38 ms. **DECISION:** Keep KLU behind the adapter for research; no return to the 60-second production Krylov chain.

**HYPOTHESIS:** Fixing solver and monotone classification would meet all gates. **EVIDENCE:** All sensitivities solved and no controllers rolled back, yet six Q trials accepted no move, 127 controllers reached max outer rounds, Full AC took 42.55 s and Vpu accuracy remained baseline. **DECISION:** Stop numerical tuning after the single run.

**HYPOTHESIS:** The pre-run `SENSITIVITY_STATION_CONTROL` provenance proved applied control. **EVIDENCE:** Accepted outer rounds were zero and every accuracy metric equaled local-PV baseline. **DECISION:** Correct provenance in final code; treat this run as fallback and FAIL.

**v7.7 gate failure.** The KLU backend removed the sensitivity bottleneck; the coupled-Q/outer-NR path is now the blocker. A code-based audit of the six rejected trials and controller sensitivity matrix is required before selecting a numerical correction. No new ILU/GMRES tuning round is justified by this iteration.
