# v6.8 HTML feature and UI inventory

Scope: source inspection of `YTBS_PowerFactory_Sebeke_Goruntuleyici_v6_8.html` only. Line references below are physical source lines; most JavaScript is compacted into long lines. No sample/model JSON was opened. This describes code paths and declared UI behavior, not runtime testing.

## Model loading and identity

- The Model tab accepts PowerFactory DGS 7.x JSON from a file picker or drop target. It parses in a worker where available, validates DGS class `Attributes`/`Values`, builds indexes and site/line relationships, and reports reference/geometry issues. See the load card at line 218, `DGSModel` construction/indexing at lines 252–274, `loadFiles` at 348, and `auditV2` at 663.
- v6.0 wraps loading to keep exactly one active model: it takes only the first supplied file, clears existing models/results, then loads and scans that file (line 699). The model list still exposes activate/remove and “clear models” actions (`renderModelList`, `activateModel`, `clearAll`, lines 330, 347, 351), but normal v6.8 loading replaces rather than accumulates models. The “compare two models” panel is hidden in the HTML (line 220); time-series plotting over `models` is consequently not reachable from the ordinary one-file flow (lines 403, 406–407, 699).
- `DGSModel.rid` is a fresh `crypto.randomUUID()` (with a timestamp/random fallback) per load, while `date`, `time`, scenario name and source version come from DGS rows (lines 253, 265–267). This makes a reload a new calculation identity even if the file contents are otherwise the same.
- The model card reports record counts, model date/time, DGS class counts and audit issues. The issue table shows only its first 35 entries and offers a CSV for the complete issue list (`fillModelInfo`, `drawIssues`, `exportIssues` event wiring, lines 321–333 and 353).
- A 315-record embedded seasonal-capacity reference is used by the capacity preflight, map details, SLD capacity box and analysis table (`EMBEDDED`/capacity setup, lines 2289–2328; `renderCapacityTable`, lines 2381–2388; SLD capacity, lines 2412–2418). Source comments explicitly treat the Excel MVA values as unverified candidates, not authoritative operating limits (lines 2337–2339, 2381).

## Inventory and operating data

- Static inventory is class-driven. The named inventory covers stations, lines, transformers, substations/bus groups, terminals, bays, generators, loads, shunts, series capacitors, switches, line/transformer types, cubicles and matrix rows (`CATEGORY`, line 241). The UI provides class, YTM, TM, nominal kV and name/FID filters plus filtered and raw-technical CSV (line 219).
- `filterStatic` searches normalized name and FID, applies TM/YTM/voltage membership rules per equipment class, and `renderStatic` pages results using the configured page size (lines 357–371). Selecting a row opens source fields and related equipment; detail actions can jump to inventory, map, or scheme (lines 377–388).
- The dynamic/operating view exposes seven groups: production P/Q, load P/Q, transformer tap, switch position, line service, shunt state, and generator voltage setpoint (`DYN_CATS`/`LABEL_DYN`, lines 243–244). `dynRows` applies model, TM and name/FID filters; the view labels `pgini/qgini/plini/qlini` as model inputs/configuration rather than solved measurements (lines 220, 391, 395). It supports filtered/raw CSV and detail-to-map navigation (lines 399–400).
- Earlier code contains multi-model comparison and hourly trend rendering (lines 403, 406–407), but the one-file override and hidden compare panel prevent those features from being used through the standard v6.8 loading UI (lines 220, 699). This is a documented reachability limitation, not a claim that the hidden implementation is broken.

## Map, filters, selection, parallel lines and flow

- The geographic map has detailed source-route and simple TM-to-TM geometry, season/capacity selection, result metric selection, result-flow animation, TM/line search and layer toggles (map markup at line 221; toolbar/filter construction at lines 2512–2522). `mapArea` is the YTM filter; `voltageLayers` supplies per-voltage line/site filters. The `mapSite` dropdown is populated from the selected YTM and voltage set, but choosing a TM selects/focuses it rather than restricting the map to only its incident lines (`refillMapSites`, `syncScope`, lines 3199–3202; `selectSite` and `drawMap`, lines 440–443). The same map scope is applied to the v6.8 lightning result inventory through `scopeOK` (lines 3303–3311).
- Map modes are geographic and scheme (`setMapMode`, line 423). The v6.8 toolbar adds nominal-voltage, loading and scenario-delta display modes, plus standard/separated line layout and legend toggle (`ensureMapControls`, line 3387). `lineStyle` uses nominal voltage colors/widths, loading gradients, service-state dashes, and scenario colors (lines 3377–3385).
- Parallel lines are grouped by sorted endpoint TM IDs (`v4ComputeParallel`, line 1168). The original offset is restricted to two-point simple geometry (`v4LinePixels`, line 1169); the v6.8 override offsets parallel paths in separated layout, including detailed route points (line 3383). Activation recomputes parallel groups (line 3393).
- Flow animation is opt-in by the map checkbox in the source UI, but v6.5 enables it by default on model activation and the v6.8 settings default `flowDefault` to true (lines 221, 3226, 3291, 3393). The legacy result animator requires a result set with usable line P and a verified terminal/orientation rule; it stops for V mode, hidden pages, leaving the map, or switching away from geographic mode (`startFlow`/`stopFlow`, lines 603–605). The smart flow layer also caps arrows per line and describes speed as visual rather than physical (lines 2594–2615, 2632).
- Model activation clears selected line/site and resets the camera (line 347). Blank-map selection reset is implemented by both the v5.4 pointer handler and v6.8 handler (lines 2543–2553 and 3389–3391). v6.8 exposes a “clear selection on blank click” setting (line 3388), but the earlier handler is unconditional and remains installed: turning the v6.8 setting off cannot disable blank-click clearing. **Confirmed UI bug.**
- YTM/voltage changes refresh the lightning inventory and map but do not clear an already selected line; the map selection/detail stays bound to that line even when its layer is filtered out (`syncScope`, lines 3201–3202; final `hookEvents`, line 3391; selection set in lines 440–444). The highlight is omitted when `visibleLine` rejects it (`drawMap`, lines 430–432). **Confirmed stale-selection behavior**; the user can see details for an item absent from the current map scope.

## Lightning/results panel and scenario actions

- The map’s lightning panel is rebuilt as compact v6.8 tabs: Results, Scenario Δ, Energize, with Lines/Transformers/Buses kinds, search, 400 kV and 66/154/220 kV quick filters (`ensurePanel`, line 3372; `render`, line 3374). Results use the selected base/scenario role and show electrical P/Q, current, loss, loading or bus V/angle values when present (`renderResults`, `lineInventory`, `trafoInventory`, `busInventory`, lines 3312–3345). Selecting a row expands details; focus actions navigate to the map.
- `Scenario Δ` requires both a base and current scenario Full AC result; it compares line/transformer flows and bus voltage/status (lines 3346–3362). `Energize` lists out-of-service or changed lines, transformers and buses, and exposes service/reset actions (lines 3363–3374). A line re-energization that is not ready for calculation leaves the user in the energization view for terminal/switch path analysis (`setLineState`, line 3365; `renderEnergize`, line 3369).
- The lightning header’s “Hesapla” and map toolbar’s “Hesapla” run Full NR against the reference or current scenario depending on overrides (`setupLightning`, line 3059; `patchToolbar`/`patchLightningCalc`, line 3209–3210; `quickCalculate`, line 3052). Legacy scenario UI is hidden/inert by v6.5 while old controls are wired to the current scenario controller (line 3213).
- Scenario state is a local overlay, not a command to PowerFactory or the physical grid. Line, switch, transformer and terminal/bus overrides, restored terminals and revision are included in the Full NR scenario identity (lines 2871–2877 and 2941–2949; v6.8 state actions at lines 3365–3368). Apply/undo/reset invalidate prior Full NR results; a changed scenario is only shown after a current scenario calculation (lines 3064, 3023–3034).

## SLD

- The SLD tab exposes station, station/regional scope, connected-line selection, scenario service off/on, map navigation and SVG download (line 222). The geographic map also has a scheme mode (lines 221, 423).
- The detailed station SLD uses DGS bay/cubicle relationships when `ElmBay` data exists; it paginates large bay lists and allows a bay drilldown. Without bay data it deliberately falls back to the existing reduced bus/branch station diagram; it does not claim to be a full PowerFactory Node-Breaker drawing (`sldFull`, line 2227; `origDrawSchemeGeneral`, line 2249; v3 fallback, line 873). The UI warns that the drawing is automatically derived and not the original project layout (line 222).
- SLD off/on actions apply local scenario overrides; SVG download exports the current generated drawing (UI line 222; handlers in the v4/v5 scenario and SLD setup around lines 1172–1208 and 1294–1328).

## Analysis engines and analysis tabs

- The Analysis tab includes a manual 66 kV+ experimental AC-PQ solve, embedded-measurement inspection, diagnostics and result categories for line P/Q/loading, bus V/angle, transformer P/Q, topology and data quality (lines 223–226; `scanEmbeddedMeasurements`, `startV3Solver`, lines 683–699 and 855–865). It explicitly says this is not a measurement and warns against operational use (lines 226, 865).
- External result/measurement file inputs are present only in a hidden compatibility panel; the UI says they are disabled and the source JSON is the single input source (lines 218, 224–226). The Excel capacity reference above remains embedded and separate from those disabled uploads.
- The added calculation center exposes **Full Network AC · Full Newton-Raphson**, **Hızlı Yaklaşık AC**, **DC Tarama** and cancel (lines 2994–2996). Full NR builds a network-wide model, runs a Web Worker, rejects stale results if model/scenario changes, and stores a result only on convergence (`buildElectricalModel`, line 2883; `runFull`, lines 2973–2987; `installResult`, lines 2960–2969). The model diagnostic states that station-controller outer-loop behavior is not implemented and PowerFactory equivalence is not claimed (lines 2996, 3062).
- Fast AC calls the older reduced 66 kV+ AC-PQ island solver and labels itself distinct from Full NR (`runFast`, line 2989; `startV3Solver`, line 855). DC uses a lossless reduced 66 kV+ model and reports P/angle only, not AC voltage/Q/loss/N-1 (`solveIslandDC`/`run`, lines 2441–2458; `runDc`, line 2990). The legacy DC path chooses scenario graph only for line or switch overrides; it does not include v6.8 transformer/bus overrides in that predicate, despite those overrides being part of current Full NR scenarios. **Confirmed scope mismatch for DC under transformer-only or bus-only scenarios.**
- The Full NR analysis hub has Summary, Voltage, Lines, Transformers, Generators, Topology and Quality pages (`setupAnalysis`, line 3063; `renderAnalysisHub`, line 3062). Its output is explicitly labelled calculated, model-scope dependent and unvalidated against PowerFactory (`resultRows`, lines 2938–2940; `fullSourceLabel`, line 3031).

## Settings and IDs

- Base settings include theme, precision, table page size, map line/site sizing, route detail and clearing loaded models (line 230). v6.8 adds persisted map settings under `ytbs_v66_map_settings`: nominal/loading/delta display, standard/separated layout, palette, four loading thresholds, line colors/widths, delta thresholds, flow default, blank-click clearing and legend visibility (lines 3290–3302, 3387–3388). Reset restores defaults; apply sorts thresholds and persists the values.
- `FID` is the source object ID and is indexed within each DGS class. Duplicate FIDs are reported during model load and the index stores the last encountered row for that class (lines 260–264). Cross-class IDs are distinguished internally by `class|FID` keys in result/scenario tables (lines 2938, 3317, 3343–3344). Aggregated electrical buses retain source ElmTerm IDs; a bus row’s key is the sorted member-terminal FID list (`busData`, line 3317; `resultRows`, line 2938).
- The optional technical-data mode reveals source FID/type/cubicle fields and a source-ID badge; normal labels prefer equipment names (`v5Id`, `clean`, `techDetails`, lines 1954–1966, 2026). Result rows retain the original class and FID, rather than creating human-readable IDs (`idFor`, line 2117; `resultRows`, line 2938). Model `rid` is a separate random session identity, not the DGS FID (line 253).

## Confirmed issues from source

1. The “clear selection on blank click” setting is ineffective when disabled because the earlier v5.4 click listener always calls `clearSelection()` on an unhit click; the v6.8 listener’s setting guard is a second listener, not a replacement (lines 2543–2553, 3388–3391).
2. YTM/voltage filter changes redraw layers but preserve `selectedLine`/`selectedSite`; the selected detail can refer to a now-hidden feature (lines 3201–3202, 3391, and selection handlers at 440–444).
3. DC scenario selection checks only line/switch override maps; transformer and bus override maps added later are not consulted by the DC run path (lines 2458, 2871–2877, 2941–2948, 3366–3367).
4. The final script labels the UI v6.8, but the v6.5 compatibility model-activation wrapper calls `versionAndCompact()`, which rewrites the title/header/footer to v6.5 (lines 3067, 3072; v6.8 labels set at line 3397). Browser baseline confirmed the title returns to v6.5 after a model load. **Confirmed version-label regression.**
