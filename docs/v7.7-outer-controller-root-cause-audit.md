# v7.7 outer controller: code-based root-cause audit

This audit uses the **sole** v7.7 real-model Full AC record, `validation/20260930-v77-sparse-direct.json`, and source at `bcaa99c4d04a7dfa4c09ce2f158f5eeaf955a473`. It performs no new real-model solve. The archived record was generated at `4b9c526`; the later `67d32d8` provenance-only correction was not rerun on that model.

## Recovery and backend

Branch `fix/v7.7-sparse-direct-station-control` was pushed to `origin` at `bcaa99c4d04a7dfa4c09ce2f158f5eeaf955a473`. Its three v7.7 commits contain the KLU adapter, WASM glue/data, bounded classification, four new tests, portable artifact, provenance correction, run JSON and final gate report. Two pre-existing, untracked v7.5/v7.6 user reports were left untouched.

`sensitivity-interleaved.ts` builds the transposed Jacobian once per classification/refresh batch. `sparse-direct.ts` converts CSR to CSC, invokes KLU analyze/factor once, packs all unique remote RHS into one `klu_solve`, checks each true residual against `1e-6`, and disposes the factor. Production defaults to KLU; Krylov requires explicit `LEGACY_KRYLOV`. `klu-js@0.1.0` is pinned, its LGPL-2.1-or-later text is committed, and the WASM data/license are embedded in the portable HTML. The committed HTML blob is 741,785 bytes, SHA-256 `1a7e24569d67c9217c034eff2dcaf476750163a9223d28950dc9b32b1aa90cb0`. The local Windows file is 741,786 bytes after line-ending conversion. The npm wrapper is young; distribution obligations warrant separate review.

The benchmark records case order `["C"]`; case D is `NOT_RUN_C_GATE`. KLU solved 313/313 RHS in two batches and two factorizations on an 8,151-dimensional, 53,535-nnz matrix. Maximum true residual was `2.8049e-10`. CSC conversion took 4.78 ms, symbolic factor 6.20 ms, numeric factor 8.15 ms and all direct RHS solves 29.38 ms. Full AC was 42,553.0 ms; 36,667.3 ms was outer trial NR. Classification was stable in one pass: 158 eligible and sensitivity-solved, zero rolled back. No outer Q round was accepted. The archived `SENSITIVITY_STATION_CONTROL` label is therefore false for this run; final code marks its unresolved, zero-round state `BASELINE_FALLBACK`. The archived grid metrics equal the local-PV baseline, including Vpu MAE `0.01696` versus the `0.0071` gate.

**Proven repeated-trial defect.** `station-controls-v73.ts` computes `moves` and `predictedNorm` before the three-attempt loop (lines 175–202). Each attempt clones the same `model`, applies the same `move.appliedDelta`, and starts NR from the same `solved` state (203–207). Rejection halves `trustFraction` (210), but does **not** recompute or scale the move inside that loop. Thus trials 1–3 are the same physical trial, as are 4–6. Their identical recorded NR outcomes confirm the source-level conclusion. At least four of the six expensive NR calls repeated a previously rejected input.

**Proven rejection condition; proposal origin unresolved.** The converged trials have finite norm ratio `1.79104`: their controller residual norm rose by about 79.1%, so actual reduction is negative. Code computes `rho` only when predicted reduction exceeds `1e-12` (206). Since these converged trials have `rho=null`, their computed predicted reduction was at most `1e-12`; the outer code nevertheless launched NR. The first three trials never produced a converged `newNorm`; the saved line-search failure does not reveal the underlying NR step diagnostics. No trial met the acceptance rule requiring actual reduction `>1e-8` and `rho>=0.1`.

`oldNorm`, `predictedNorm`, predicted/actual reduction, NR total iterations, requested/applied maximum ΔQ, radius/Q clamps, per-trial active/free controller count, and the failed NR line-search step diagnostics are **not saved**. The controller code records only seven trial fields (207); the browser engine forwards that array and the benchmark copies it unchanged. Absolute norms and Q-step sizes cannot be reconstructed from this JSON. The last coupled-system dimensions give context, not a reliable per-trial controller count.

The one sensitivity refresh occurs after the first three failed trials (212, 172–173). With zero accepted Q rounds, `model` and `solved` did not advance; it refactorized at the same operating point for 155 remaining RHS. The first two dense-system diagnostics after refresh exactly repeat the initial 147-column values. **Stale sensitivity after an accepted operating-point change is not supported by this record.**

## Dense controller S matrix

The source forms `S[row, column]` from each remote-bus voltage sensitivity and the column controller's direction-dependent active-unit sharing (170). The least-squares solver scales columns, forms `SᵀS`, Cholesky factors it, regularizes, then solves (39–55). Q headroom and dispatched-power weights can change the effective columns (in `station-participation.ts`). The proposal loop removes directionally exhausted controls and clamps a requested step to `controlScale × trustFraction` and unit Q limits (175–199).

Saved coupled-system dimensions were `147→147→132→132→114→114→111→109→108` before refresh, then `147→147→133→133→132→131`. All 15 solves reported `REGULARIZED`. The first 147-column solve reported Cholesky pivot count 147; the direction-changed second reported 8 before regularization. This is **not** a robust numerical rank estimate: `rank` is the count of pivots before Cholesky first stops. The `conditionEstimate` values around `6.7e7` are ratios of pivots in the **regularized Gram matrix**, capped near the solver's target; they are not condition numbers of S. The second 147-column solve used regularization `0.00384`, versus `0.00000417` in the first. This supports a fragile direction-dependent controller subproblem, but does not establish its precise cause.

The saved per-controller records contain only own-control effective slope and per-unit slopes, not cross-controller entries of S. Among 158 eligible controls, all 158 remote-bus IDs and actuator-bus sets are distinct; no pair shares an actuator bus; 70 controls have multiple actuator buses. Own-control slope magnitudes range `0.000202`–`0.067841` pu/MVAr (median `0.037618`); 153 are negative and 5 positive. This **does not** prove a sign bug: the full cross-coupling matrix and finite-difference Q→V comparison are absent. Near-zero **rows/columns**, row/column correlations, duplicate or near-duplicate voltage objectives, and per-controller Q headroom cannot be evaluated from the archived fields. There is no saved full S matrix, target-voltage/current-Q list or per-trial active-set mapping. Unique remote IDs rule out exact same-bus duplicates only.

## Hypothesis, evidence, decision

**HYPOTHESIS:** The sparse solver remains the bottleneck. **EVIDENCE:** 313 RHS succeeded at residual `2.805e-10` in 29.38 ms direct-solve time; outer trial NR took 36.67 s. **DECISION:** Keep KLU; do not resume ILU/GMRES tuning.

**HYPOTHESIS:** Halving trust fraction retries smaller Q steps. **EVIDENCE:** `moves` is built before the retry loop and remains unchanged; matching outcomes appear in each trial triple. **DECISION:** Reject this assumption. Before another model benchmark, a synthetic test should verify that each attempted trial has a distinct, bounded applied Q vector after a trust reduction.

**HYPOTHESIS:** Dense matrix rank/conditioning alone explains all rejected trials. **EVIDENCE:** The Gram factor is regularized, one directional pass stops at pivot 8, but the archived S entries and predicted norms are missing. **DECISION:** Treat conditioning, active-set clipping and sign/scaling as unproven contributors. Do not prescribe SVD, pivoting or another backend from this record.

**HYPOTHESIS:** Recomputing sensitivities at a new operating point would resolve the six trials. **EVIDENCE:** No Q step was accepted; the refresh used the unchanged state and the first dense diagnostics repeated. **DECISION:** Staleness is not established here.

## Minimum correction proposal and readiness

No numerical correction is implemented in this audit. The smallest justified next work is in `station-controls-v73.ts`: record the complete proposed and applied Q vector summary, old/predicted/new norms, reductions, active/free/saturated counts, NR iterations and failure details; reject a non-descent prediction **before** full NR; and recalculate a distinct bounded proposal when trust is reduced. A small synthetic test in `tests/unit/v73-station-control.test.ts` should prove retry inputs differ and predicted/actual acceptance use the same controller set. If the dense direction still fails a predicted-descent check, inspect its saved S submatrix and headroom before selecting a new controller method. `tools/ytbs-benchmark-v73.ts` may need to retain new summary fields, although it currently forwards trial objects unchanged.

**Final benchmark readiness: NO.** The outer proposal has a proven duplicate-retry defect and a proven non-improving converged trial, while missing diagnostics prevent attribution of the bad proposal to a specific dense-matrix mechanism. The fixed acceptance gates and one-run budget remain in force. A new real-model run requires the user's approval after a concrete synthetic-verified correction; none was run for this audit. Main and release were not merged.
